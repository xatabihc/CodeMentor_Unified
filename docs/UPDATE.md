# Сборка, проверки и обновление

**Навигация nav1:** подписанный инкрементальный APK находится в `android-studio/app/build/outputs/apk/debug/app-debug-navigation.apk`. Способ сборки и ограничения — [MOBILE-NAVIGATION.md](MOBILE-NAVIGATION.md). Он отличается от старого app-debug.apk. Для обновления поверх версии с той же подписью используйте `adb install -r` с новым файлом; данные приложения не очищать.

Текущее состояние 2.1.0-dev: [проверки и ограничения](DEVELOPMENT-2.1.md). APK в ограниченной сессии не собран.

## Проверки без Android

Из корня проекта (Python 3 и Node.js):

```bash
bash tools/test.sh
python3 tools/reference_solutions.py | node tools/worker_coverage.js
```

Вторая команда — отчёт об ограничениях веб-движка, а не требование полного покрытия.

## Android

Нужны JDK 17, Android SDK 35 и доступные зависимости Maven/Google. При необходимости задайте sdk.dir в игнорируемом android-studio/local.properties либо ANDROID_HOME. Не коммитьте абсолютный локальный путь.

```bash
bash tools/build-apk.sh
cd android-studio
./gradlew --no-daemon lintDebug
```

После assembleDebug скрипт автоматически проверяет каждый упакованный веб-ресурс через tools/check_apk.py. CPython в APK пока не включён; worker.js — проверяющий поднабор Python на JavaScript.

Ожидаемый файл после успешной сборки: android-studio/app/build/outputs/apk/debug/app-debug.apk.
Wrapper закреплён на Gradle 8.13, AGP — 8.13.2. Системный Gradle не используется. При недоступном домашнем каталоге можно задать GRADLE_USER_HOME внутри проекта, но для Gradle всё равно нужны разрешённые локальные сокеты и зависимости. В текущей ограниченной сессии APK не собран.

## Обновление с сохранением прогресса

1. В работающей старой версии экспортировать JSON через настройки; сохранить копию отдельно.
2. Использовать тот же applicationId `com.codementor.offline`, ту же подпись и больший versionCode. Для текущей 2.1.0-dev-nav1 установлен 211 (предыдущая dev — 210) (предыдущие версии: 2.0.1 — 201, 2.0 — 200).
3. Установить обновление поверх старого приложения, например `adb install -r ПУТЬ_К_APK`. Не удалять приложение и не очищать его данные.
4. Проверить прохождение, попытки и черновики. Новая версия читает прежний ключ LocalStorage, затем сохраняет прогресс и в приватные настройки Android. JSON по-прежнему имеет format codementor-progress и version 1.
5. При смене подписи Android отклонит обновление. Использовать прежний ключ; debug APK на разных машинах часто подписаны разными debug-ключами. Не обходить это удалением приложения с ценными данными.

## Приёмка на устройстве

- Пройти урок, оставить обычный и пустой черновики, свернуть приложение, остановить процесс и открыть заново. Проверить статус, попытки и оба черновика.
- Проверить смену раздела, переключение урока во время проверки, экспорт/импорт, отмену файлового диалога, неверный JSON и старую SQLite-копию через конвертер.
- Поворот в обе стороны при открытой клавиатуре; маленький экран, большой системный шрифт, вертикальная прокрутка до последней кнопки, масштабирование, области системных панелей.
- Авиарежим: все уроки и проверка начального маршрута доступны; внешняя ссылка открывается отдельным браузером.
- Установить обновление поверх прежней подписанной версии. Проверить, что WebView/PWA-кэш показывает новые ресурсы после повторного открытия.

## Git

В этой сессии .git доступен только для чтения, поэтому история и коммит не созданы. В обычном терминале на хосте:

```bash
git init
git status --short --ignored
```

Проверить список перед добавлением файлов. .gitignore исключает local.properties, IDE-настройки, ключи, БД прогресса, экспортированные JSON и сборки. Личные имя/email Git следует настроить по собственным данным; в проект они не записывались. Не заменять непустую существующую историю.
