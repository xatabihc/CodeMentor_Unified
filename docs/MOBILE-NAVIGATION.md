# Android: мобильная навигация 2.1.0-dev-nav1

## Причина и исправление

В MainActivity системные отступы задавались как padding самой WebView, при этом её границы оставались размером с корневую область. Обработчик учитывал systemBars(), не учитывал displayCutout() на API 30+, и возвращал исходные Insets. В HTML/CSS не было safe-area-inset-top, верхняя панель имела разрыв строки между меню и хлебными крошками, а минимальная область кнопки составляла 44px. Это не обеспечивало устойчивой безопасной области для HTML-элементов при edge-to-edge на targetSdk 35. Фактическое воспроизведение на конкретном Samsung без ADB не подтверждено.

Существующий обработчик заменён, дополнительный патч поверх него не устанавливался:

- WebView помещена в FrameLayout. Отступы применяются к контейнеру, поэтому уменьшаются реальные границы WebView, включая её HTML fixed/sticky элементы.
- На Android 11+ корневая область явно получает edge-to-edge Insets. Для сторон берётся максимум systemBars и displayCutout; снизу — максимум безопасной области и IME, а не их сумма.
- Обработанные типы обнуляются перед передачей в WebView; уведомления при скрытии клавиатуры продолжают поступать. Такой подход предотвращает повторный/застрявший отступ; он соответствует [рекомендации Android для WebView](https://developer.android.com/develop/ui/views/layout/webapps/understand-window-insets).
- На API 26–29 учитывается только пересечение контейнера с оставшейся видимой областью. Если decor/adjustResize уже убрали статус-бар или клавиатуру, повторный отступ равен нулю. SafeAreaTest проверяет эту геометрию.
- После изменения размеров контейнера Insets запрашиваются повторно. Системные панели не скрываются; fullscreen/immersive флаги не добавлялись. Светлая верхняя область использует тёмные значки статуса на API 30+.
- CSS использует env(safe-area-inset-*, 0px) для PWA. В Android эти значения получают нулевые уже обработанные Insets: один системный отступ, один владелец. Для header и sidebar нет суммирования одного safe-top дважды: у header это padding, у отдельного fixed-sidebar — позиция top.

## Кнопки, панель и доступность

Открытие и закрытие — 54×54 CSS px, с контрастным фоном и значками 26px. При viewport initial-scale=1 это 54×54 dp на Android. Область нажатия не сокращается при нехватке ширины.

Header состоит из одной flex-строки; длинное название обрезается многоточием. Верхняя панель остаётся доступной при прокрутке уроков. Sidebar ограничен безопасной областью, его шапка и кнопка закрытия закреплены при внутренней прокрутке. Мобильный режим включает короткий landscape до 1024×500, чтобы меню не исчезало при повороте телефона.

Добавлены aria-controls/aria-expanded, исключение закрытого меню и фона открытого меню из фокуса, возврат фокуса на открывающую кнопку, Escape и удержание Tab внутри панели. Изменение размеров не перерисовывает редактор и не сбрасывает фокус/черновик. При явном открытии меню фокус переходит к кнопке закрытия; клавиатура обычно закрывается как следствие смены фокуса.

Хранилище, формат JSON, applicationId, проверяющий Python-поднабор и учебные материалы не менялись. Сохраняются 170 уроков и 36 уроков маршрута. CPython в исходном APK 2.0.1 не был упакован; исправление навигации не добавляет и не удаляет Python runtime.

## APK и способ сборки

Получен файл:

`android-studio/app/build/outputs/apk/debug/app-debug-navigation.apk`

Версия **2.1.0-dev-nav1 / 211**, пакет com.codementor.offline, debug-подпись совпадает с сохранённым APK 2.0.1.

Обычный `bash tools/build-apk.sh --offline --stacktrace` повторно остановился до Android-задач: Gradle не может создать локальный сокет (`Could not determine a usable wildcard IP`). **Успешный assembleDebug не заявляется.**

APK создан отдельной офлайн-инкрементальной сборкой через SDK Build Tools 35.0.0: javac → D8, aapt2 для нового манифеста, zipalign, apksigner. Полностью пересобраны классы приложения; библиотечный DEX, R DEX, Android resources и прочие исходные файлы сохранены из базового APK. Кэшированные DEX побайтно сверены с ним, исходный manifest/dependencies защищены проверками. resources.arsc хранится без сжатия и выровнен для Android 11+. Сборка не требует изменения совместимых зависимостей или записи вне проекта; существующий debug-ключ только читается.

Команда для этого конкретного сохранённого базиса:

```bash
python3 tools/build-navigation-sdk.py --baseline backups/mobile-navigation-20261101-225018
```

Это не универсальная замена чистой Gradle-сборки. Если изменены нативные Android-ресурсы, зависимости или манифест, нужна полная Gradle-сборка в обычной среде. Детали входов и SHA256 текущего кода/ресурсов/APK записаны рядом в app-debug-navigation.build.json; SHA256 APK — в app-debug-navigation.apk.sha256.

Для обновления поверх совместимо подписанной установленной версии:

```bash
adb install -r android-studio/app/build/outputs/apk/debug/app-debug-navigation.apk
```

В этой сессии установка не выполнялась. Не удалять приложение и не очищать его данные. После обновления повторно открыть приложение и проверить кэш новой версии, прогресс, оба направления поворота, системные жесты/трёхкнопочную панель, клавиатуру, прокрутку и касание всей области обеих кнопок меню.
